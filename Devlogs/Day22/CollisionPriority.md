# 동시 충돌 우선순위 조사

---

## 확인된 동작

플레이어의 `SnakeExternalCollision.OnTriggerEnter2D`는 적 직접 충돌과 장애물 충돌을 콜백이 들어온 순서대로 처리한다. 전체 무적이 없는 상태에서 같은 물리 스텝의 콜백을 아래 순서로 호출한 독립 재현에서 결과가 달랐다.

- 적 → 장애물: 몸통 1칸 손실 후 공용 HP 25 피해, 직접충돌 보호와 전체 무적 적용.
- 장애물 → 적: 공용 HP 25 피해와 전체 무적이 먼저 적용돼 몸통 손실이 차단됨.
- 기존 전체 무적 또는 자기충돌에 따른 전체 무적이 먼저 적용된 경우: 이후 직접 충돌과 장애물 피해 차단.

`Tests/CollisionPriorityRepro`는 실제 외부·자기 충돌 스크립트를 연결하고 Unity 시간·충돌체·몸통·체력·무적을 대체한다. 인자 없이 실행하면 안내만 표시하며, `obstacle-first` 인자로 실행하면 아직 수정되지 않은 역순 결함을 보여주므로 **실패가 예상된다**. Unity 물리 시뮬레이션이나 실제 보호막·화면 조작을 검증하지는 않는다.

---

## 수정 보류 사유

장애물 처리만 다음 `FixedUpdate`로 미루면 같은 물리 스텝의 적 투사체와 근접 HP 피해가 새 장애물 무적보다 먼저 처리될 수 있다. 다음 물리 스텝 전에 일시정지·보호막 만료·회복·파괴가 발생하면 접촉 당시의 결과도 달라질 수 있다. 따라서 제품 코드에는 단순 지연을 적용하지 않았다.

---

## 겹침 선조회 검토

장애물 콜백에서 겹친 적과 몸통을 먼저 조회하는 방식도 검증 없이 적용할 수 없다.

- 적이 1초 직접충돌 보호 종료 후에도 계속 겹쳐 있다가 장애물에 닿으면, 새 적 진입이 없는데도 단순 겹침 조회가 적을 다시 처리할 수 있다. 이전 스텝의 접촉 쌍과 해당 스텝에서 선처리한 쌍을 구분해야 한다.
- 기하학적 겹침은 무시된 충돌 쌍과 반드시 같지 않다. 레이어 매트릭스와 `IgnoreCollision` 외에도 Collider2D·Rigidbody2D별 레이어 오버라이드와 콜백·접촉 캡처 레이어를 고려해야 한다. Collider2D 배열 기반 접촉 조회와 트리거의 실제 동작은 PlayMode 확인이 필요하다.
- 이 프로젝트는 물리 Transform 자동 동기화가 꺼져 있다. 몸통 손실은 꼬리 오브젝트의 제거를 지연하고 나머지 몸통 Transform을 이동시키므로, 같은 콜백 안의 조회가 삭제 예정인 몸통이나 이전 물리 위치를 반환하는지 확인해야 한다.
- 투사체 콜백이 장애물보다 먼저 오면 장애물 콜백에서만 조회하는 방식으로는 이미 적용된 투사체 피해를 되돌릴 수 없다. `IsTouching`은 마지막 물리 업데이트의 접촉 상태를 사용하므로 첫 트리거 콜백 시 다른 신규 접촉을 모두 볼 수 있는지도 실측이 필요하다.

접촉 쌍 기록은 개선 후보지만 트리거 최초 진입·지속·종료, 비활성화·삭제, 무시 설정 변경, 여러 물리 스텝과 여러 머리 콜라이더의 순열을 PlayMode에서 검증하기 전에는 안전성이 확인되지 않았다.

---

## 다음 구현 방향

자기충돌, 적 직접 충돌, 엘리트 절단, 장애물, 투사체와 근접 피해를 같은 물리 스텝 단위로 수집한다. 기존 전체 무적을 확인한 뒤 직접 몸통 손실, 장애물과 신규 무적, 나머지 HP 피해 순으로 해결하는 방안을 검토한다. 보호막 흡수는 기존 체력 처리 경로를 재사용하고 파괴되는 투사체의 피해 정보는 값으로 보존한다.

일반 `LateUpdate`는 렌더 프레임에 여러 물리 스텝이 들어갈 수 있으므로 스텝별 물리 처리 직후의 안전한 해결 시점을 Unity에서 확인해야 한다. 일시정지, 객체 파괴, 중복 충돌, 보호막 만료와 다양한 충돌 순열의 PlayMode 테스트가 필요하다. 현재 프로젝트는 2D 물리 `FixedUpdate` 모드를 사용하며 Unity는 해당 모드에서 `FixedUpdate` 직후 물리 시뮬레이션을 수행한다.
