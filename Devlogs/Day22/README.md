# 22일차: 초반 플레이 충돌 및 설정 입력 수정

---

## 발견한 문제

- 21일차 Unity 플레이에서 시작 직후 몸통이 3칸에서 1칸으로 감소했고 18초에 패배했다.
- 몸통 초기화가 경로 초기화보다 먼저 실행돼 몸통이 머리와 겹친 채 첫 물리 판정에 들어갈 수 있었다.
- 일시정지 또는 레벨업 중 설정창을 열면 뒤쪽 게임 화면이 ESC나 숫자 입력을 처리할 수 있었다.

---

## 변경과 검증

경로 기록기를 몸통 관리자보다 먼저 초기화하도록 실행 순서를 조정했다. 설정 화면과 입력 재설정 중에는 뒤쪽 합성·일시정지·레벨업의 키보드 및 마우스 선택을 차단한다. 독립 회귀 테스트는 실제 프로젝트 코드를 사용하되 Unity 컴포넌트와 입력을 대체한다.

Unity 배치에서 설정 중 가상 ESC와 숫자 1, 뒤쪽 실제 버튼 이벤트를 차단하고 설정 종료 후 정상 선택과 만석 교체 ESC 우선순위를 확인했다. 이 시험은 레벨업 경험치와 만석 슬롯을 강제로 만들었으며, 사용자 키 설정은 변경하지 않았다.

몸통 HUD는 현재 수와 성장 최대를 `Body 3 / 3`으로, 절대 최대를 `(max 20)`으로 구분한다. 손실·성장·복구 시 수치를 갱신하며 기존 HUD 호출 방식도 유지한다.

실제 Unity 사본에서 몸통 API를 직접 호출하는 통제 시험으로 시작·성장·손실·복구·성장 최대 재설정과 HUD 재활성화를 확인했다. 최대 문구의 필요 너비는 267.6이고 텍스트 영역은 420으로 측정됐다.

수정 후 Unity 사본의 정상 속도 배치 플레이에서 첫 물리 판정 이후에도 몸통 3칸과 HP 100이 유지됐다. 회전과 가속 입력 없이 진행하고 레벨업 첫 후보를 자동 선택한 별도 실행은 22.6초에 패배했으므로 5분 생존이나 자연 진행 엘리트 보상은 입증하지 못했다. Unity Editor 검색 인덱싱 중 `ArgumentOutOfRangeException` 한 건이 기록됐으며, 게임은 이후에도 실행됐다.

별도 배치에서는 가상 키보드로 A·D 회전과 Space 가속을 자동 조작하고, 무적과 능력치 변경 없이 정상 속도로 300.1초 생존했다. 일반 적 3종과 4분 엘리트의 자연 출현을 확인했으며 종료 상태는 몸통 2칸, HP 100이었다. 회피 위주 조종으로 레벨 1과 경험치 0에 머물렀으므로 성장 핵심 루프나 사람이 직접 조작한 플레이로 간주하지 않는다. 배치 포커스 문제를 피하기 위해 입력 설정의 메모리 사본만 시험 중 조정했다.

또 다른 Unity 배치 실행에서는 출현기 시각을 240초로 강제하고 엘리트를 강제 처치했다. 대형 경험치 보석 1개와 보상 요청 1개, 서로 다른 후보 3개, 일시정지, 실제 무기 보상 버튼 이벤트와 장착·재개를 확인했다. 이 실험은 자연 진행으로 4분을 생존한 검증이 아니다.

통제된 전투 배치에서는 플레이어 이동과 자연 스폰을 끄고 충돌체 없는 정지 표적 10개를 배치했다. 머리 사거리 밖이면서 첫 몸통 무기 사거리 안의 표적에 실제 자동 공격이 적중해 10회 처치와 소형 보석 10개 획득, 레벨 2와 몸통 4칸 성장, 선택 중 일시정지, 실제 보상 버튼 이벤트와 무기 장착·재개를 확인했다. 자연 전투 난이도 검증은 아니다.

적 직접 충돌과 장애물이 같은 물리 틱에 발생할 때 콜백 순서에 따라 결과가 달라지는 미해결 문제는 [동시 충돌 조사](CollisionPriority.md)에 정리했다.
