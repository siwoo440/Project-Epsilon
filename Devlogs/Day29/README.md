# 29일차: 경험치 보석 자동 병합

---

## 개발 방향

경험치 보석이 많아지면 머리의 자동 흡수 범위 밖에서 인접 보석을 합쳐 오브젝트 수를 줄인다. 기획서의 소형 1·중형 5·대형 20은 임시 경험치 값이다.

기획서에 조합 개수는 정해져 있지 않다. 이번 구현은 경험치를 정확히 보존하는 임시 방식으로 소형 5개를 중형 1개로, 중형 4개를 대형 1개로 합친다. 그 외 값은 그대로 남긴다.

---

## 적용 방식과 임시값

Game 씬에 병합 관리자를 연결했다. Inspector에서 발동 개수 100개, 인접 거리 1.5, 게임 시간 검사 간격 1초, 검사당 최대 4그룹·기준 보석 32개·이웃 검사 예산 512를 조정할 수 있다. 게임이 진행 중일 때만 검사하며 흡수 범위 안 보석과 수신자가 다른 보석은 함께 합치지 않는다.

새 기준 순회를 시작할 때 화면 밖을 먼저, 그 안에서는 머리로부터 먼 보석을 먼저 검사한다. 계속 생기는 새 보석 때문에 기존 보석이 영구히 밀리지 않도록 한 번 시작한 기준·이웃 순회는 고정된 보석 ID 목록을 끝까지 따르며, 새 후보는 다음 순회에서 반영한다. 따라서 매 검사마다 현재 화면 밖이나 가장 먼 보석을 엄격히 먼저 고르는 방식은 아니다. 후보가 수집·비활성화되거나 이동하면 부분 그룹을 다시 검증한다.

자체 획득과 병합 소비는 `Destroy` 전에 즉시 소비를 표시해 같은 프레임 중복 획득·병합·재설정을 차단한다. 다른 코드가 보석 GameObject에 `Object.Destroy`를 직접 호출하는 경우에는 Unity의 지연 파괴 전 소비 표시를 할 수 없어 같은 프레임 제외를 보장하지 않는다. 현재 제품에는 그런 외부 호출 경로가 없다. 활성 보석 목록은 검사 시 Unity에서 조회하며 별도 정적 등록부를 유지하지 않는다. 씬 로드와 관리자 비활성화 시 부분 검사 상태를 지운다.

---

## 검증과 한계

제품 규칙을 사용하는 독립 시험 11개는 경험치 합계, 단계·거리·발동 경계, 우선순위, 수신자와 흡수 대상 제외, 재료 중복 방지, 검사 예산, 작은 예산의 부분 그룹, 동적 후보 삽입과 재료 변경을 확인했다. 제품 보석·관리자를 사용하고 Unity 객체를 대체한 독립 시험 10개는 수집과 지연 파괴, 설정 간격·일시정지, 비활성·재활성, 수신자 분리, 화면 밖 우선, 재설정 차단, 실제 거리 검사 예산, 씬 전환 상태 정리를 확인했다. 두 시험의 종료 코드는 0이다.

검사 예산은 이웃 후보 검사와 병합 직전 거리 재검증을 제한한다. 전체 활성 객체 검색, 후보마다 수행하는 머리 거리 계산, 후보 정렬과 고정 ID 목록 구성에는 이 예산이 적용되지 않는다. 고립·밀집 후보를 각각 10회 계획한 별도 .NET 시험에서 1,000개는 평균 0.384·0.272ms, 10,000개는 2.102·2.718ms, 100,000개는 25.177·31.310ms였다. 이는 Unity 프레임 성능이 아니며 보석이 매우 많을 때 정렬과 목록 비용으로 한 프레임 지연이 발생할 수 있다. 이전 중간 알고리즘의 100,000개 고립 후보 측정은 약 85ms였다. 실제 PC와 Unity에서 성능을 측정해 조정해야 한다.

Unity 실제 Game 씬에서 28일차 코드의 관리자 부재 red는 종료 코드 1이었다. 제품 반영 후 같은 시험은 종료 코드 0으로 통과했으며 첫 검사 우선순위, 소형 5→중형과 중형 4→대형의 경험치 보존, 일시정지, 비활성·재활성, 외부 `Destroy` 완료 후 제외, 실제 보석 획득 XP 5를 확인했다. 측정된 첫 검사에서는 그룹 1개, 인접 후보 검사 5회, 예산 대상 거리 계산 13회, 전체 후보의 머리 거리 계산 15회였다. 별도의 저예산 Unity 배치도 종료 코드 0으로 통과했다. 검사당 거리 예산 17·기준 보석 1개·병합 그룹 1개로 제한하고 여러 프레임에 걸친 후보 보존, 새 보석 삽입, 재료 이동·복귀, 실제 머리 수집 후 대체 보석을 통제해 경험치 보존과 병합을 확인했다.
