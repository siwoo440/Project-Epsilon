# 31일차: 비활성 물리 충돌 처리

---
## 확인한 문제

Unity는 충돌체가 활성화된 경우 비활성 `MonoBehaviour`에도 2D 트리거 메시지를 보낼 수 있다. 외부 충돌 처리기와 자기 충돌 처리기는 비활성 중에도 충돌을 처리하거나 예약할 수 있었고, 적 행동과 적 투사체에도 같은 활성 상태 확인이 빠져 있었다. 현재 일반 전투 코드에서 이 네 컴포넌트를 직접 비활성화하는 호출은 확인되지 않았으므로, 컴포넌트만 비활성화되는 수명주기 경계로 구분한다.

---
## 변경 내용

- 플레이어 외부 충돌과 자기 충돌, 적 지속 접촉, 적 투사체의 물리 콜백 입구에서 컴포넌트 활성 상태를 확인한다.
- 공개 직접 판정 API와 활성 상태의 충돌 우선순위, 적 공격과 투사체 처리 경로는 유지한다.
- 비활성 중 들어온 접촉은 예약하거나 피해를 적용하지 않는다. `Enter` 콜백은 재활성 뒤 충돌체가 분리되고 다시 진입할 때 새 접촉으로 처리한다.

---
## 검증

- `Tests/DisabledPlayerCollision`: 변경 전 제품 코드에서 비활성 외부 충돌, 동일 물리 스텝 안의 자기 충돌 재활성, 비활성 자기 충돌 대체 경로가 실패했다. 수정 후 제품 코드 참조 시험 4개와 비활성 상태의 공개 외부·자기 충돌 직접 호출이 통과했다.
- `Tests/CollisionPriorityRepro`: 장애물·적 콜백 순서, 자기 충돌 순서, 기존 무적, 일반 피해, 비활성화와 재등록, 즉시 처리 대체 등 10개 시나리오가 통과했다.
- 30일차 실제 Unity 물리 red는 비활성 외부 충돌 HP 75, 자기 충돌 예약 후 몸통 3→1, 비활성 근접 적 HP 90, 비활성 적 투사체 HP 92와 파괴를 재현했다. 종료 코드는 1이며 활성 대조와 보호막 회귀는 통과했다. 동일 스크립트의 수정본 실제 Unity green은 종료 코드 0으로 네 비활성 경계의 무피해, 자기 충돌 같은 스텝 재활성 전 예약 없음과 몸통 3 유지, 적 투사체 재활성 후 HP 92, 동시 장애물·투사체 보호막을 확인했다. 위 독립 시험은 Unity 물리 엔진을 실행하지 않는다.

## 남은 작업

- 컴포넌트를 비활성화하는 게임 기능을 추가할 때 충돌체와 연관 수명주기를 함께 검토한다.
