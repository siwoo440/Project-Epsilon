# 50일차 전투 기록과 이름 정비

---

## 변경 내용

실행 인수 `-epsilonRecord`가 있을 때만 전투 기록기를 생성한다. `-epsilonSeed 13579`처럼 정수 시드를 추가할 수 있다. 기록 파일은 승리 또는 패배 시 Unity의 `Application.persistentDataPath` 아래 `CombatRecords`에 고유한 JSON으로 저장한다. 저장 실패는 전투 종료와 영구 성장 저장을 중단하지 않는다.

실제 시작 조건과 10초 간격 상태, 포탑 구성 변경, 종료 상태를 남긴다. 누적 경험치, 전체·보상 대상·소환 적·보스 처치, 현재·성장 최대 몸통, 체력과 슬롯을 분리한다. 유효한 피해는 근접·투사체·보스 돌진·위험 지역·직접 충돌·절단 등으로 구분하고 보호막 흡수와 직접 몸통 손실도 기록한다. 적 직접 충돌에는 보스 접촉도 포함될 수 있다. 기록은 전투가 정상적으로 승패에 도달해야 파일로 저장된다.

포탑 에셋 56개의 표시 이름을 점검하고 플레이 가능한 48개 이름을 고유한 한글 이름으로 유지했다. 포탑 이름의 시험용 접두사와 영문 표시를 제거하고 레벨업·합성·엘리트 보상과 포탑 해금의 관련 문구를 한글로 정리했다. 내부 식별자와 에셋 파일명은 기존 저장 및 참조를 위해 유지했다. 수치는 여전히 조정 대상이다.

---

## 실행과 비교

게임 실행 인수에 `-epsilonRecord -epsilonSeed 13579`를 지정한다. 두 기록의 시작 조건과 결과는 `python Tools/compare_run_records.py 첫번째.json 두번째.json`으로 비교한다. 종료 코드 0은 비교한 시작 조건 일치, 2는 시작 조건 차이, 1은 입력 오류다. 같은 시드라도 입력 시각과 프레임·물리 순서가 다르면 전투 결과는 달라질 수 있으며 완전한 재생 기능은 아니다.

---

## 확인 결과와 한계

Unity 6000.3.21f1의 별도 제품 프로필 사본에서 전투 기록을 두 차례 검증했다. 실제 경험치 42, 일반 적과 소환 적의 처치 구분, 무적 제외, 보호막·체력 피해, 예약된 보스 위험 피해, 자기 충돌, 보스 절단 패배와 JSON 저장을 통제 조건에서 확인했다. 동일 시드의 두 기록은 비교한 시작 조건이 일치했고 시드를 변경한 기록은 차이를 보고했다.

포탑 56개 이름과 실제 보상 문구 검사, 보상 화면의 한글 글꼴 연결 검사, 기본 실행 시 기록기 비생성 검사, 충돌 우선순위·보스 돌진·엘리트 보상·보상 배치·49일차 화면 회귀는 배치 종료 코드 0이었다. 테스트는 실제 씬과 통제된 입력·피해를 사용하며 5분 자연 전투나 사용자 수동 조작의 증거는 아니다. 일부 Unity Editor Search 초기화 예외가 게임 테스트와 별도로 관찰됐다.

전체 C# 251개 파일을 살펴 중괄호만 있는 줄의 주석을 제거하고 필요한 한국어 설명을 보강했다. 주석을 제외한 코드 텍스트의 불변을 대조했고 주석 정리 후 49일차 화면 회귀를 실행했다. 실제 게임 화면에서 한글 글꼴의 글자 표시와 보상 카드의 잘림은 별도 확인 대상이다.
