# 51-A 화면별 씬 분리

---

## 구성

`MainMenu`는 시작·영구 성장·설정을 담당하고, `Preparation`은 실제 해금 상태를 확인해 캐릭터·맵·시작 포탑을 선택한다. 기존 `Game`은 전투와 일시정지·보상 패널을 담당하며 `Results`는 실제 승패·성과·저장 상태와 재도전·메뉴 복귀를 표시한다. 빌드는 이 순서로 설정했다. 기존 SampleScene 설정은 보존하되 활성 빌드에서 제외했다.

캐릭터·맵·시작 포탑은 준비 화면에서 선택하고, 전투 씬의 기존 초기화기가 준비된 다음 기존 장착 로직으로 적용한다. 종료 시 기존 관리자와 저장 실패 상태를 결과 씬까지 유지한다. 재도전과 메뉴 복귀는 저장을 먼저 확인하고 이전 관리자를 제거한다. `Game` 씬을 직접 열면 기존 단일 씬 메뉴·출격 흐름을 유지한다.

---

## 배치 검증

분리 씬과 빌드 순서 검사는 Unity 종료 코드 0이었다. 실제 버튼 이벤트로 메인 설정·키 설정, 캐릭터와 맵 잠금, 해금된 중장형과 두 번째 맵·포탑 선택, 전투 능력치와 장착, 패배, 저장 실패 중 재도전 차단, 저장 복구 후 재도전, 등록 보스 처치와 승리·다음 맵 해금, 메인 메뉴 복귀를 확인했다. 재도전은 이전 캐릭터와 맵을 유지한다. 이는 가상 버튼과 직접 등록한 시험 보스를 사용하는 통제 시험이다.

초기 통합 시험에서 동적으로 추가된 화면이 캐릭터 초기화보다 먼저 출격해 선택값 대신 기본값을 적용하는 오류가 재현됐다. 실제 초기화 순서를 확인하고 한 프레임 대기 후 기존 장착 로직을 실행하도록 수정한 뒤 재시험했다. 기존 Game 씬의 메뉴·충돌·엘리트 보상·합성·전투 기록 회귀도 확인했다.

원본 작업 공간에서 외부 변경된 `Game.unity`는 덮어쓰지 않았고, 변경 시점 SHA-256 `E9F5959B56C2A341103A9AD632B11C90DA410D15B3A19BA504780E793DCB8760`인 사본에서도 씬 전환을 검사했다. 기존에 삭제 상태였던 SampleScene 파일과 사용자가 변경한 솔루션 파일은 이 작업에 포함하지 않았다.

## 직접 확인할 사항

실제 빌드와 에디터 화면에서 해상도별 글자·버튼 위치, 캐릭터·맵·포탑 이미지, 마우스와 키보드 조작을 확인해야 한다. 새 씬 흐름을 통한 5분 수동 플레이는 실행하지 않았다. Unity의 Search 인덱싱 예외는 게임 시험과 별도로 발생할 수 있다.
